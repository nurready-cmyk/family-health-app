# PRD — Приложение для здоровья семьи
**Product Requirements Document**
Версия 1.0 · Июнь 2026

---

## 1. Обзор проекта

### 1.1 Идея
Веб-приложение для отслеживания здоровья семьи — ввод анализов, визуализация динамики, рекомендации по питанию и спорту, дневник тренировок и питания. Без платных сервисов, без сервера, полностью на GitHub Pages.

### 1.2 Проблемы, которые решает продукт
1. Не знаю свои показатели здоровья и в каком состоянии органы
2. При болезни не понимаю первопричину
3. Не знаю, зарождается ли сейчас какое-то заболевание
4. Ем всё подряд, не хватает дисциплины исключать вредное
5. Не занимаюсь спортом системно
6. Хочу улучшить уровень энергии

### 1.3 Цель продукта
Сервис улучшает здоровье и поднимает энергию через данные, рекомендации и привычки.

## 2. Пользователи

| Профиль | Описание |
|---|---|
| Пользователь 1 | Основной (муж) — вводит свои анализы, тренировки, питание |
| Пользователь 2 | Супруга — отдельный профиль, свои данные |

**Переключение профилей** — одна кнопка в шапке. Данные каждого профиля хранятся отдельно в localStorage.

## 3. Платформа и технический стек

| Параметр | Решение |

## 4. Экраны приложения

### 4.1 Дашборд (главная)

**Назначение:** Быстрый обзор состояния здоровья за день / неделю.

**Содержимое:**
- Приветствие с именем и датой
- Переключатель профилей (Я / Супруга)
- Индекс здоровья — итоговый балл от 0 до 100 на основе последних анализов (норма / отклонение)
- Уровень энергии дня — вводится вручную ползунком (1–10), накапливается в график
- Карточки быстрого статуса: последний анализ, последняя тренировка, цель дня
- Топ-3 рекомендации дня (питание / спорт / образ жизни)
- Мини-график динамики одного ключевого показателя (гемоглобин или другой по выбору)
- Кнопка «Что сегодня сделал?» — быстрый ввод активности дня
- Баннер «Внимание» — если есть показатели за пределами нормы

**Логика индекса здоровья:**
```
Индекс = (количество показателей в норме / общее количество показателей) × 100
```
Цвет: зелёный (80–100), жёлтый (50–79), красный (0–49).

---

### 4.2 Анализы

**Назначение:** Ввод, хранение и просмотр результатов анализов крови и других обследований.

**Содержимое:**
- Форма добавления анализа: дата, тип (общий анализ крови / биохимия / гормоны / другое), показатели с единицами измерения
- Таблица введённых показателей с подсветкой нормы (зелёный / красный)
- Загрузка PDF или фото бланка через FileReader API (для справки, не парсится)
- История всех дат сдачи анализов
- Кнопка экспорта всех анализов в JSON

**Поддерживаемые показатели (стартовый список):**

| Показатель | Единица | Норма (муж) | Норма (жен) |
|---|---|---|---|
| Гемоглобин | г/л | 130–170 | 120–155 |
| Эритроциты | ×10¹²/л | 4.0–5.5 | 3.7–4.7 |
| Лейкоциты | ×10⁹/л | 4.0–9.0 | 4.0–9.0 |
| Тромбоциты | ×10⁹/л | 150–400 | 150–400 |
| Глюкоза | ммоль/л | 3.9–6.1 | 3.9–6.1 |
| Холестерин общий | ммоль/л | < 5.2 | < 5.2 |
| АЛТ | Ед/л | < 41 | < 31 |
| АСТ | Ед/л | < 40 | < 32 |
| Ферритин | нг/мл | 30–300 | 12–150 |
| Витамин D | нг/мл | 30–100 | 30–100 |
| ТТГ (щитовидка) | мЕд/л | 0.4–4.0 | 0.4–4.0 |

Возможность добавить свои показатели вручную.

---

### 4.3 Динамика

**Назначение:** Визуализация изменений показателей во времени.

**Содержимое:**
- Выбор показателя из выпадающего списка
- Линейный график с зонами нормы (зелёная полоса)
- Точки на графике — даты сдачи анализов
- Подсказка при наведении: значение, дата, статус (норма / выше / ниже)
- Переключатель периода: 3 мес / 6 мес / 1 год / всё время
- Раздел «Тенденция»: растёт, падает, стабильна (автовычисление по последним 2 значениям)
- Сравнение двух показателей на одном графике (опционально)

**Библиотека:** Chart.js — подключается через CDN, бесплатно.

---

### 4.4 Рекомендации

**Назначение:** Персональные советы по питанию, спорту и образу жизни на основе анализов.

**Логика (без ИИ — правила в JS):**

Если показатель вышел за пределы нормы → система берёт из базы знаний (JS-объект) соответствующие рекомендации.

**Примеры правил:**

| Отклонение | Рекомендация питание | Рекомендация спорт |
|---|---|---|
| Гемоглобин низкий | Говядина, гречка, шпинат, витамин C | Умеренные кардио, избегать истощения |
| Глюкоза высокая | Исключить сахар, белый хлеб, сладкие напитки | Ходьба 30 мин после еды |
| Холестерин высокий | Омега-3, овощи, клетчатка | Кардио 3× в неделю |
| Витамин D низкий | Жирная рыба, яйца, солнце | Прогулки на улице |
| Ферритин низкий | Красное мясо, бобовые, орехи | Снизить интенсивность тренировок |

**Содержимое экрана:**
- Список активных рекомендаций (только по показателям с отклонением)
- Карточка каждой рекомендации: показатель → что не так → что есть → что делать
- Раздел «Что исключить» и «Что добавить» в питании
- Раздел «Фокус недели» — одна главная цель, выбранная автоматически по наибольшему отклонению
- Возможность отметить рекомендацию как выполненную

---

### 4.5 Тренировки (фитнес-дневник)

**Назначение:** Запись тренировок, план упражнений, рекомендации по восстановлению.

**Содержимое:**
- Форма добавления тренировки: дата, тип (силовая / кардио / растяжка / йога / другое), длительность, упражнения
- Ввод упражнений: название, подходы, повторения или время
- После сохранения — автоматическая рекомендация по восстановлению (на правилах):
  - Силовая → белок в течение 30 мин, сон 8 ч, следующая тренировка через 48 ч
  - Кардио → вода, электролиты, лёгкая растяжка
- Календарь тренировок — точки по дням месяца
- Статистика: тренировок за неделю / месяц, общее время
- Раздел «Рекомендованный план» — базовые программы под цель (набор энергии / здоровье сердца / общий тонус)

---

### 4.6 Питание

**Назначение:** Дневник питания, связь продуктов с витаминами и показателями здоровья.

**Содержимое:**
- Быстрый ввод приёма пищи: время, продукты (текстом)
- База продуктов с витаминным составом (JS-объект, ~50 продуктов на старте):
  - Гречка → B1, B2, железо, магний
  - Говядина → B12, железо, цинк, белок
  - Шпинат → железо, витамин K, фолиевая кислота
  - и т.д.
- Автоматический подсчёт витаминов за день (приблизительный)
- Сравнение с рекомендуемой суточной нормой (%)
- Раздел «Закономерности»: какие продукты едятся чаще, чего не хватает
- Связь с анализами: если низкий B12 → показывает, каких продуктов не хватает в дневнике

---

### 4.7 Цели и отчёт

**Назначение:** Постановка целей по здоровью, отслеживание прогресса, периодический отчёт.

**Содержимое:**
- Создание цели: название, показатель, текущее значение, целевое значение, срок
  - Пример: «Поднять гемоглобин с 110 до 130 до 1 сентября»
- Прогресс-бар каждой цели
- Раздел «Что сегодня сделал» — ежедневный чек-ин (текст + галочки)
- Еженедельный отчёт: выполнено / не выполнено по целям, динамика показателей
- Геймификация:
  - Очки энергии за активности (тренировка +10, правильное питание +5, сон +5)
  - Достижения-бейджи: «7 дней подряд», «Первый анализ», «Цель достигнута»
  - Общий уровень энергии — визуальная шкала

---

### 4.8 Профили

**Назначение:** Управление двумя профилями семьи.

**Содержимое:**
- Карточки профилей: имя, аватар (инициалы), дата последнего анализа, индекс здоровья
- Переключение активного профиля
- Экспорт данных профиля в JSON (для резервной копии)
- Импорт данных из JSON
- Сброс данных профиля

## 5. Хранение данных

Все данные хранятся в `localStorage` браузера. Структура ключей:

```
health_profile_1        → { name, gender, birthYear }
health_profile_2        → { name, gender, birthYear }
health_analyses_1       → [ { date, indicators: { hb: 120, glucose: 5.1, ... } } ]
health_analyses_2       → [ ... ]
health_workouts_1       → [ { date, type, duration, exercises: [...] } ]
health_nutrition_1      → [ { date, meals: [...] } ]
health_goals_1          → [ { title, metric, current, target, deadline } ]
health_energy_log_1     → [ { date, level, points } ]
health_checkins_1       → [ { date, done: [...], notes } ]
health_active_profile   → "1" или "2"
```

**Лимит localStorage:** ~5–10 МБ на домен — достаточно для нескольких лет данных.

**Экспорт / импорт:** Кнопка «Скачать резервную копию» — сохраняет все ключи в один JSON-файл. «Восстановить» — загружает файл обратно.

## 6. Рекомендательная система (без ИИ)

Логика построена на JS-объекте `RULES`:

```javascript
const RULES = {
  hb_low: {
    trigger: (val, gender) => val < (gender === 'm' ? 130 : 120),
    food: ['говядина', 'гречка', 'шпинат', 'гранат', 'витамин C'],
    avoid: ['чай и кофе сразу после еды (блокируют железо)'],
    sport: 'умеренные нагрузки, избегать истощения',
    priority: 'high'
  },
  glucose_high: {
    trigger: (val) => val > 6.1,
    food: ['овощи', 'цельнозерновые', 'бобовые'],
    avoid: ['сахар', 'белый хлеб', 'сладкие напитки', 'картофель'],
    sport: 'ходьба 30 мин после еды, кардио 3× в неделю',
    priority: 'high'
  },
  // ...и т.д. для каждого показателя
}
```

При сохранении новых анализов система проходит по всем правилам и формирует список активных рекомендаций.

## 9. Нефункциональные требования

| Параметр | Требование |
|---|---|
| Скорость загрузки | < 2 секунды на мобильном |
